
= ASysC

**ASysC** (Analog System Compiler) is a circuit compiler that symbolically
processes circuit equations written in a compact rule-based language, compiles
them to Python models, and simulates transient or AC behavior.

The component rules describe physical relationships. For example, a resistor
connects its voltage and current using Ohm's law:

[source,text]
----
NAME.CR(@1, @2, R) := {
    NAME.U = ACROSS(@1, @2);
    NAME.I = THROUGH(@1, @2);
    NAME.U = R * NAME.I
};
----

The `@1` and `@2` parameters represent the resistor terminals. Circuit netlists
instantiate components and connect their terminals; examples are available in
the link:examples[examples] directory, and component definitions are in
link:rules/components.rule[components.rule].

== Project layout

[cols="1,3",options="header"]
|===
|Path | Contents
|link:src/lib/[src/lib/] | Symbolic expression engine
|link:src/app/[src/app/] | ASysC command-line compiler
|link:rules/[rules/] | Component, algebra, and evaluation rules
|link:examples/ac/[examples/ac/] | AC-analysis circuits and plotting scripts
|link:examples/transient/[examples/transient/] | Transient-analysis circuits and plotting scripts
|link:doc/[doc/] | Project documentation and figures
|===

Each example directory normally contains a `.cir` netlist and a
`simulation.py` script. The compiler generates a Python model from the netlist;
the script runs the simulation and plots its results.

== Requirements

- GNU Make
- A C++ compiler: `g++` or `clang++`
- Python 3
- Python packages: NumPy and Matplotlib

On Debian or Ubuntu, install the compiler and Python packages with:

[source,shell]
----
sudo apt install build-essential python3 python3-numpy python3-matplotlib
----

== Get the source

[source,shell]
----
git clone https://github.com/analog-system-compiler/asysc.git
cd asysc
----

== Build

Build the compiler and generate the Python models for the examples:

[source,shell]
----
make -j4
----

The `-j4` option compiles up to four C++ files in parallel; adjust the number
to suit your machine. To remove compiler and generated example outputs before
building again, run:

[source,shell]
----
make clean
make -j4
----

Optional build settings can be passed as Make variables:

[source,shell]
----
make USE_CLANG=1       # Build with clang++ instead of g++.
make DEBUG=1           # Include debug symbols and enable assertions.
make TEST=1 bin/asysc  # Enable the built-in checks at startup.
----

The `TEST=1` checks run when the resulting `bin/asysc` executable starts.
`make run` below is separate: it runs the example circuit simulations.

== Run the examples

Run every example simulation from the repository root:

[source,shell]
----
make run
----

To generate the Python models without running the plots, use:

[source,shell]
----
make -C examples
----

To run one example, first generate its model, then run its script from that
example's directory. For example:

[source,shell]
----
make -C examples
cd examples/ac/rc_low_pass
python3 simulation.py
----

The plotting scripts open Matplotlib windows; use a graphical session or
configure a non-interactive Matplotlib backend if running without a display.

== Use the compiler directly

The command-line compiler accepts a circuit netlist, a Python output path, and
an analysis type (`ac` or `trans`). For example:

[source,shell]
----
./bin/asysc \
  -i examples/ac/rc_low_pass/rc_low_pass.cir \
  -o /tmp/rc_low_pass.py \
  -t ac
----

For command-line help, start the compiler without arguments and enter `help`.
Enter `exit` to leave the interactive console.

== Documentation and contributing

The full documentation is available on
https://analog-system-compiler.github.io/asysc/[GitHub Pages].

Build the HTML or PDF version with:

[source,shell]
----
make html
make pdf
----

Rule files in link:rules/[rules/] define components and symbolic
transformations; keep new rule files consistent with the lowercase naming
convention and update `rules/includes.rule` when adding a rule that should be
loaded by default.

Before submitting changes, build the compiler and run the relevant example or
test. The `make header` target updates source license headers.

== Example analyses

The transient examples show how circuit voltages and currents evolve over time.
They include a delay line, a divide-by-four circuit, Graetz-bridge and
single-diode rectifiers, an op-amp integrator, an NE555 oscillator, NPN biasing,
a logic-gate oscillator, and an RLC step response. Several examples expose
component values with sliders so you can explore how parameter changes affect
the waveform.

image::doc/images/trans_analysis.png[Transient-analysis examples]

The AC examples show frequency-dependent circuit behavior. The RLC filter plot
shows the individual response curves as component values vary, while the
Sallen-Key plot shows the filter's gain and phase across frequency.

image::doc/images/ac_analysis.png[AC-analysis examples]
